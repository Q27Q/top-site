## 下一阶段实施方案（尚未启用）

1. 优先试验 B站按 UID 的最新作品枚举，核验作者、原帖绝对时间、置顶与分页；搜索只用于发现候选，详情 owner.id 必须匹配配置 UID。至少跨 48 小时低频测试，再决定是否上线。
2. 微博、抖音、快手先确认可用的数据授权路径或人工提供的作品永久链接；如果需要登录态，另行明确凭据来源、使用范围和运行环境。本次不接入登录抓取、不尝试绕过验证。
3. 每个平台独立适配器、超时和错误处理。建议试运行每 30–60 分钟检查一次，失败指数退避，保留最后一次有效缓存。频率需根据实测再调整，不承诺实时。
4. 同步器输出统一记录 `{id, accountId, platform, url, publishedAt?, text?}`；以平台作品 ID 去重；核验账号归属和永久链接。标题为空可省略，不用主页冒充作品。
5. 以平台和账号为单位记录检查结果，全部目标完成后才汇总该平台成功时间；失败记录独立时间。单平台失败不覆盖其他平台的数据，不清空旧动态。
6. 部署候选是独立定时任务生成静态 JSON 或 Worker 定时任务写缓存。先验证宿主环境的网络可用性，再选择方案。保持页面只读取统一数据，抓取策略变化不改 UI。
7. 人工兜底已可通过编辑 `data/updates.json` 使用；只有实际核实的作品才入库。未知发布时间为 null 或省略，不能填收录时间代替。

## 验收门槛

连续检查稳定；指定账号没有串号；链接指向具体作品；已知时间与原帖一致；重复、置顶、删除和失败不破坏旧数据；平台故障互不影响。达到这些条件后再实现生产自动同步。

工具维护备注：检测到 Agent Reach v1.6.0 可用，本次沿用现有 v1.5.0，没有升级环境。如需升级可另行请求“帮我更新 Agent Reach：https://raw.githubusercontent.com/Panniantong/agent-reach/main/docs/update.md”。
